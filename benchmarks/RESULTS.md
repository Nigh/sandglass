# 实测记录

环境：Linux x64，Intel Core Ultra 7 265K，Node v24.9.0。没有手机硬件。

## CPU 物理压力测试

命令：`npm run benchmark -- --output=benchmarks/physics.json`。1,000 / 5,000 / 10,000 粒各实际运行至少 60 秒。交替向下堆积、零输入、连续翻转、高幅值 `(35,-80,20) m/s²` 和向上堆积，并切换材料。此表为每个 1/120 秒物理外步的 CPU 耗时，不是帧时间或 GPU 耗时。

| 粒子数 | 实际时长 s | 平均步耗时 ms | P95 ms | P99 ms | 模拟时间 / 实际时间 |
|---:|---:|---:|---:|---:|---:|
| 1,000 | 60.001 | 2.152 | 8.746 | 18.075 | 3.863 |
| 5,000 | 60.080 | 31.421 | 120.391 | 188.668 | 0.265 |
| 10,000 | 60.247 | 135.338 | 367.122 | 474.952 | 0.062 |

所有档位采样中：非有限状态 0、边界违反 0、粒径改变 0，粒子数守恒。采样不是每个子步的全量轨迹证明。最小浮点边界余量约 -7.39e-9 m，低于校验容差。

**结论：** 该 CPU 后端在此极端运动压力场景下，5,000 和 10,000 粒不具备实时 120 Hz 吞吐量；它们是手动压力档，不是已认证的移动推荐档。1,000 粒是当前保守起点，仍不能据此承诺手机 30 FPS。高速度导致全局 CFL 子步数上升，是当前吞吐量边界。CPU 基准不包含 Worker 传输和渲染。物理与浏览器压力验证部分时间并行，结果不是隔离实验室跑分。

## 浏览器

桌面无头 Chromium 使用 SwiftShader 软件 GPU。浏览器基准记录以 `browser.json` 原始结果为准；CPU 提交时间与 GPU 时间严格区分。没有执行 WebGPU 或 WebGL 浮点物理后端，不能提供这些后端的性能数字。

浏览器：HeadlessChrome 156.0.8078.4，1100×850 CSS 像素。以下为完整渲染循环的真实帧时间；每档持续至少 60 秒。自动降低像素比与外观复杂度有效，不删除粒子。

| 粒子数 | 实际时长 s | 平均 FPS | 帧 P95 ms | 帧 P99 ms | CPU 渲染提交平均 ms | 丢弃模拟时间 s |
|---:|---:|---:|---:|---:|---:|---:|
| 1,000 | 60.032 | 25.23 | 66.8 | 100.1 | 0.317 | 4.033 |
| 5,000 | 60.017 | 14.68 | 133.4 | 183.3 | 0.268 | 44.008 |
| 10,000 | 60.053 | 10.64 | 200.0 | 233.3 | 0.257 | 51.225 |

GPU 耗时为不可用。CPU 提交平均耗时不包含 GPU 执行，不代表渲染完成时间。超过追赶预算的物理时间已公开统计，不能把高档位称作维持原物理时间精度的实时模拟。**这些软件 GPU 结果未达到 30 FPS，不能用于宣称移动性能达标。**

工程验收：31 项单元测试全部通过；TypeScript 检查与生产构建通过；浏览器权限/幅值/互斥/失效恢复/布局检查通过。评审发现的启动控件竞态、降级后外观选择框不一致均修复，并由 `--degradation` 浏览器回归验证。构建仍提示入口包超过 500 kB：约 537.6 kB、gzip 138.9 kB；未通过隐藏提示冒充零警告。

生产包另以 `vite preview` 启动验证：实际 WebGL 场景初始化、1,000 粒固定步推进、无致命错误、0g 控件成功改变最终输入。该检查是生产资源运行烟测，不替代 60 秒性能基准。
